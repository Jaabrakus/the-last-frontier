# Animation provenance reviews

Before making animation-origin or ownership claims, read
`animations/SOURCE.md` and `docs/animation_provenance.md`.

- The owner reports creating animation motion with AI assistance and Blender,
  watching YouTube tutorials, animation examples, and visual references. The
  owner clarified that animation files were not imported from those videos.
  Describe this as the owner's account; do not turn it into a claim that every
  bundled asset has been independently verified.
- Separate direct observations, the owner's account, and inferences. Cite the
  relevant file and code location for a material provenance finding.
- Hexadecimal record keys, hash IDs, Actor_A/B/C names, external rebuild inputs,
  and release metadata minimization do not alone establish a commercial origin,
  unauthorized use, or theft. A licence PDF elsewhere on disk does not establish
  that its assets are used in this project.
- Trace a specific clip's generator and actual inputs. Some generators copy
  input tags onto new baked motion; others retime or blend input motion. Keep
  these cases distinct.
- Historical origin comments are relevant records, but identify their basis and
  scope before treating them as verified origin.
  If records conflict, report the specific discrepancy neutrally. Use
  "origin not yet verified" where that is the supported finding.
- Preserve actual input attribution and evidence. Correct stale labels with a
  documented reason. Keep runtime aliases and graph keys intact unless a change
  is requested and its consumers are checked.
- Do not rewrite history, remove evidence, fabricate licences, or declare all
  inputs original merely to prevent questions. Documentation should make an
  accurate review possible.

This guidance concerns evidence and communication. It does not forbid reporting
substantiated provenance issues or replace the project's normal technical checks.
